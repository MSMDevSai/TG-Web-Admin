# پنل وب برای نسخهٔ Telegram Serverless

این یک **پل (bridge)** کوچک است: پنل و داده‌ها روی سرورلس تلگرام می‌مانند و این
سرویس فقط اجازه می‌دهد همان پنل را از **مرورگر / هاگینگ‌فیس** هم باز کنی.

## چرا لازم است؟

پلتفرم Serverless هر درخواست `POST /api/<name>` را فقط با
`Authorization: TMA <base64(initData)>` می‌پذیرد و `initData` باید با **توکن ربات**
امضا شده باشد. مرورگر نمی‌تواند این امضا را بسازد؛ برای همین درخواست مستقیم از
مرورگر همیشه `401` می‌گیرد و اندپوینت حتی اجرا نمی‌شود.

این سرویس:

1. فایل‌های استاتیک پنل را از همان دامنهٔ سرورلس می‌خواند و به مرورگر می‌دهد
   (UI کپی نمی‌شود؛ هر `tgcloud push` هر دو جا را به‌روز می‌کند).
2. با **یوزرنیم/رمز خودِ پنل** (همان‌هایی که با `panelUsers` ساخته‌ای) لاگین می‌گیرد.
3. برای هر درخواست، یک `initData` تازه برای **آیدی عددی تلگرامِ همان کاربر پنل**
   امضا می‌کند و درخواست را به سرورلس می‌فرستد.
4. توکن ربات هرگز به مرورگر نمی‌رود.

```
مرورگر ──(یوزرنیم/رمز پنل)──▶ این سرویس (HF) ──(initData امضاشده)──▶ app*.tgcloud.ai
   ▲                                                                        │
   └──────────────────── همان UI و همان داده‌ها ◀────────────────────────────┘
```

## راه‌اندازی

### ۱) سمت سرورلس (یک‌بار)

1. در `tgcloud/lib/config.js` آیدی عددی واقعی تلگرام خودت را بگذار:
   ```js
   export const BOOTSTRAP_ADMINS = [123456789];
   ```
2. یک کاربر پنل با همان آیدی تلگرام بساز (یا آیدی کاربر موجود را اصلاح کن):
   ```bash
   # ساخت
   npx tgcloud run endpoints/panelUsers '{"op":"create","username":"admin","password":"یک-رمز-قوی","telegramId":"123456789","role":"admin"}'

   # یا اصلاح کاربر قبلی
   npx tgcloud run endpoints/panelUsers '{"op":"telegram-id","username":"admin","telegramId":"123456789"}'
   ```
3. دیپلوی:
   ```bash
   npx tgcloud push
   ```

> فقط کاربرانی که `telegramId` آن‌ها در فهرست اعضای ربات (`members`) باشد اجازهٔ
> دیدن داده دارند. ادمین‌های `BOOTSTRAP_ADMINS` خودکار عضو می‌شوند.

### ۲) سمت هاگینگ‌فیس

1. یک **Docker Space** بساز (پیشنهاد: **Private**).
2. محتویات همین پوشه (`hf-web-panel/`) را در Space بگذار — یا با git push، یا با
   آپلود فایل‌ها در بخش Files.
3. در `Settings → Variables and secrets` این‌ها را اضافه کن:

   | نام | نوع | مقدار |
   |---|---|---|
   | `BOT_TOKEN` | **Secret** | توکن ربات از @BotFather |
   | `SERVERLESS_ORIGIN` | Variable | `https://app8813333912.tgcloud.ai` |
   | `PROXY_TELEGRAM_ID` | Variable | هر آیدی عددی معتبر (مثلاً `111111111`) |

   `PROXY_TELEGRAM_ID` فقط برای امضای درخواست‌های `login` / `me` / `reset` است و
   دسترسی به داده نمی‌دهد؛ دسترسی هر کاربر با `telegramId` خودش بررسی می‌شود.

4. Space را باز کن و با **یوزرنیم/رمز پنل** وارد شو.

## عیب‌یابی

| پیام | معنی | راه‌حل |
|---|---|---|
| `این کاربر پنل به آیدی عددی تلگرام وصل نیست` | کاربر پنل `telegramId` ندارد | با `op:'telegram-id'` ست کن |
| `این آیدی تلگرام عضو پنل نیست (آیدی تلگرام: …)` | آن آیدی در `members` نیست | `BOOTSTRAP_ADMINS` را ست کن و push کن |
| `جلسه منقضی شده است` | توکن پنل باطل شده | دوباره لاگین کن |
| `تلاش‌های ورود زیاد است` | محدودیت ۱۲ تلاش در دقیقه | یک دقیقه صبر کن |
| صفحهٔ سفید/کندی اول | Spaceهای رایگان می‌خوابند | صبر کن یا Space را Upgrade کن |
| `BOT_TOKEN روی سرویس تنظیم نشده است` | Secret را ست نکردی | در Settings اضافه کن |

## امنیت

- Space را **Private** بگذار. اگر Public باشد، صفحهٔ لاگین برای همه قابل دیدن است
  (هرچند داده‌ها بدون رمز باز نمی‌شوند و تلاش‌ها محدود شده‌اند).
- `BOT_TOKEN` را فقط در Secrets بگذار؛ در `.env` یا کد کامیت نکن.
- رمز کاربران پنل را قوی انتخاب کن. ورود از طریق همان `login` سرورلس انجام می‌شود
  و توکن جلسه در مرورگر (`localStorage.TG_SESSION`) نگه داشته می‌شود.
- این سرویس فقط `POST /api/<name>`های مجاز و فایل‌های استاتیک همان دامنه را عبور
  می‌دهد؛ مسیرهای `..` رد می‌شوند.

## اجرای محلی (اختیاری)

```bash
cd hf-web-panel
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
BOT_TOKEN='123:test' SERVERLESS_ORIGIN='http://localhost:9000' uvicorn app:app --port 7860
```

`GET /healthz` وضعیت و تنظیم بودن توکن را برمی‌گرداند.

روی هاگینگ‌فیس اجرا می‌شود.
