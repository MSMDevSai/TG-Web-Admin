# پنل تلگرام — نسخه‌ی Telegram Serverless

دستیار AI روی اکانت بیزینس تلگرامت + پنل Mini App (ورود با آیدی عددی، نقش ادمین/کاربر، آرشیو کامل پیام‌ها و رسانه‌ها حتی بعد از حذف).

## ساختار

```
tgcloud/                  ← تنها بخشی که روی تلگرام اجرا می‌شه
  schema.js               جدول‌ها (اعضا، چت‌ها، پیام‌ها، ویرایش‌ها، آرشیو رسانه، ...)
  handlers/               آپدیت‌های تلگرام (پیام بیزینس، ویرایش، حذف، ری‌اکشن، دکمه‌ی اعلان، ...)
  endpoints/              توابعی که Mini App صدا می‌زند (چت‌ها، پیام‌ها، ارسال، آپلود، رسانه، تنظیمات، اعضا)
  lib/                    منطق مشترک (ingest، AI، اعلان، آرشیو رسانه، احراز هویت، ...)
web/                      فرانت Mini App (بدون build)
dev/                      تست‌های محلی (deploy نمی‌شن)
tgcloud.jsonc             تنظیم میزبانی فرانت
```

## راه‌اندازی (یک‌بار)

1. **BotFather:** Serverless روشن (انجام شده). همچنین `Bot Settings → Business Mode` را روشن کن.
2. **تلگرام (نیازمند Premium):** `Settings → Business → Chatbots` → ربات را وصل کن و دسترسی پاسخ دادن/حذف پیام بده.
3. **پروژه را بساز** (تا نسخه‌ی CLI و فایل‌های راهنما با خودت هم‌خوان باشن):
   ```bash
   npm create @tgcloud/bot panel
   cd panel
   ```
   سپس پوشه‌های `tgcloud/` و `web/` و فایل `tgcloud.jsonc` این بسته را روی پروژه کپی کن (فایل `tgcloud/handlers/message.js` نمونه را جایگزین کن). پوشه‌ی `dev/` و `package.json` اختیاری‌اند.
4. **`tgcloud/lib/config.js` را ویرایش کن:** `BOOTSTRAP_ADMINS` = آیدی عددی خودت (و هر ادمین ثابت دیگر).
5. ```bash
   npx tgcloud login      # توکن CLI از BotFather → Serverless → CLI Access
   npx tgcloud push
   npx tgcloud migrate    # همه‌ی تغییرات safe را تأیید کن
   ```
6. `push` آدرس `https://app<ID>.tgcloud.ai/` را چاپ می‌کند. آن را در `config.js` بگذار (`WEBAPP_URL`)، دوباره `push` کن و در BotFather به‌عنوان Mini App / Menu Button ربات ثبت کن.
7. هر عضو یک‌بار به ربات `/start` بزند (برای اعلان‌های تلگرامی لازم است).
8. پنل را باز کن ← ⚙️ ← کلید Gemini را وارد و ذخیره کن.

## نقش‌ها

| | ادمین | کاربر |
|---|---|---|
| دیدن چت‌ها، آرشیو (رسانه/حذف‌شده)، تاریخچه‌ی ویرایش | ✅ | ✅ |
| ارسال متن/رسانه/ویس، ری‌اکشن، ویرایش پیام خودمان، پین و بی‌صدا کردن چت | ✅ | ✅ |
| حذف پیام از تلگرام (در پنل می‌ماند) | ✅ | ❌ |
| تنظیمات AI، کلید، پرامپت، تنظیمات کلی | ✅ | ❌ |
| مدیریت اعضا | ✅ | ❌ |

آیدی‌های `BOOTSTRAP_ADMINS` همیشه ادمین‌اند و از پنل حذف/تنزل نمی‌شوند. بقیه را ادمین‌ها از 👥 اضافه می‌کنند. اگر عضو نامجازی پنل را باز کند، آیدی عددی خودش را می‌بیند تا به ادمین بدهد.

## رفتار مهم

- **تایمر AI:** هر پیام مخاطب `ai_delay_seconds` (پیش‌فرض ۲۸ ثانیه) صبر می‌کند؛ اگر پیام جدیدتری از مخاطب بیاید همان اجرای جدید جواب می‌دهد، و اگر خودت/پنل در این فاصله جواب بدهی AI ساکت می‌ماند. حالت «در حال آماده‌سازی» در پنل دیده می‌شود.
- **آرشیو:** پیام‌ها هرگز پاک نمی‌شوند. حذف توسط مخاطب فقط علامت 🗑 می‌زند؛ ویرایش‌ها متن قبلی را در تاریخچه نگه می‌دارند؛ بایت عکس/ویس/ویدیو/استیکر/فایل (تا سقف تنظیم‌شده) در دیتابیس ذخیره می‌شود. ویدیو مسیج ثبت می‌شود ولی بایتش پیش‌فرض ذخیره نمی‌شود (تنظیم دارد).
- **اعلان:** خود ربات پیام جدید را در پیوی اعضا می‌فرستد (با دکمه‌ی «بستن اعلان این چت» و «باز کردن در پنل»). خاموش‌کردن: کلی (ادمین)، هر چت، و شخصی (`/notify off` یا 🔔 در پنل).
- **تفاوت‌ها با نسخه‌ی قبلی:** تاریخچه‌ی ارسالی به Gemini سقف دارد (`ai_history_limit`)؛ AI در گروه‌ها پیش‌فرض خاموش است (از تنظیمات هر چت روشن می‌شود)؛ برچسب `sai:dev AI Assistant:` از تنظیمات قابل حذف است.

## تست

```bash
sh dev/test.sh      # ۴۴ بررسی روی SDK ساختگی + SQLite (نیاز: Node 22.5+)
```
این تست‌ها منطق خود پروژه را می‌سنجند، نه رفتار واقعی پلتفرم.

## چیزهایی که هنوز روی پلتفرم واقعی تأیید نشده‌اند (به این ترتیب تست کن)

1. **تایمر ۲۸ ثانیه‌ای** — مستندات از timer/محدودیت زمان اجرا حرفی نمی‌زنند. تست: `ai_delay_seconds` را ۱۰ بگذار، از یک اکانت دیگر پیام بده و ببین جواب می‌آید یا اجرا قطع می‌شود (لاگ: `npx tgcloud run handlers/business_message '{...}'`).
2. **آپدیت‌های بیزینسی** — `npx tgcloud webhook` را بزن و ببین `business_message`، `edited_business_message`، `deleted_business_messages`، `business_connection`، `message_reaction`، `callback_query` در `allowed_updates` هستند.
3. **ورود با آیدی** — `npx tgcloud run endpoints/boot '{}' --ctx '{ initData: { user: { id: <آیدی‌تو>, first_name: "x" } } }'`.
4. **حذف/ویرایش بیزینسی و ری‌اکشن** — قابلیت‌های وابسته به دسترسی‌های Business هستند؛ خطاها با پیام فارسی در پنل نشان داده می‌شوند.
5. **ویس از Mini App** — مرورگر داخلی تلگرام فرمت‌های مختلفی تولید می‌کند (ogg/m4a/webm). ارسال به ترتیب voice ← audio ← document امتحان می‌شود. اگر webm شد ویس واقعی نمی‌شود و باید تبدیل به ogg را اضافه کنیم.
6. **حجم JSON** — رسانه‌ها تکه‌های ۳۸۴KB با base64 رد و بدل می‌شوند؛ اگر پلتفرم سقف کوچک‌تری برای پاسخ endpoint دارد، `CHUNK` در `endpoints/media.js` و `upload.js`/`app.js` را کم کن.
7. **اندازه‌ی دیتابیس** — سقف حجم SQLite در مستندات نیامده؛ ذخیره‌ی رسانه را با `archive_max_mb` و `archive_media` کنترل کن.

## هنوز بازنویسی نشده (فاز بعد، بعد از دیباگ هسته)

مدیریت گروه (بن/میوت/حذف گروهی و فیلتر محتوا — در نسخه‌ی قبل هم فقط ذخیره می‌شد و اعمال نمی‌شد)، پنل استیکر/گیف، فوروارد پیام، پین پیام داخل چت، ویرایش پروفایل ربات، عکس پروفایل مخاطب‌ها، نمایش استیکرهای متحرک (tgs)، و اپ اندروید/ویندوز (در Serverless endpoint عمومی وجود ندارد).
